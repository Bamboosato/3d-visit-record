## 2. 目的と背景

### 2.1 背景と位置づけ
別プロジェクトの `3d_rain_viewer` は、JAXA AW3D30 の 3D 地形上に気象庁ナウキャストや JAXA GSMaP の雨雲を重ねて「地点の天候を確認すること」を主目的としたアプリです。お気に入り地点の登録やローカルバックアップ機能を備えていますが、天候観測に最適化されているため、訪問体験（行った日付・期間、思い出メモ、今後の訪問計画、将来の写真添付）を蓄積・管理する用途には特化していません。

本アプリ **3D Visit Record** は、`3d_rain_viewer` で培った **高速な 3D 地形描画・自由なカメラ視点記憶・OSM/国土地理院連携検索・堅牢なローカル保存・モバイル PWA 最適化** を土台として分離・発展させ、**「これまで訪問した地点」と「これから訪問したい予定の地点」を立体地図上で記録・計画・振り返りでき、Google Drive へ安全に保存・復元できる専用アプリ** を構築することを目的とします。

### 2.2 `3d_rain_viewer` との役割分担（削除・継承・新規）

| 区分 | 方針 | 主な対象機能・要素 |
| :--- | :--- | :--- |
| **削除（本アプリ対象外）** | 気象・降水関連の UI とデータ取得を完全に切り離す | 気象庁ナウキャスト / 今後の雨、JAXA GSMaP、タイムラインバー（`TimelineBar`）、降水量推移グラフ（`RainfallChart`）、雨量凡例（`Legend`）、降水データ設定項目 |
| **継承・発展** | 3D 地図体験と検索・保存の堅牢な基盤を引き継ぎ、全球・大量地点向けに拡張 | WebGPU/WebGL2 3D 地形描画（JAXA AW3D30）、OPFS タイルキャッシュ、3 種ベースマップ、4 カテゴリ（自然・観光・生活・その他）、OSM 周辺施設サジェスト＆キーワード検索、日本百名山 100 座プリセット、GPS 現在地ジャンプ、3D 視点共有、IndexedDB 原子的保存・Undo 保護、SW 更新ブロッカー、PWA/セーフエリア最適化 |

## 4. 初版（v1）スコープ定義

### 4.1 初版（v1）に含まれる範囲（In Scope）
1. **3D 地形マップ（全球対応）**: WebGPU/WebGL2 + AW3D30 による立体表示、3 種ベースマップ切替、標高強調調整。
2. **訪問済み／訪問予定の登録・管理**: 地点（名前・カテゴリ・座標・標高・3D 視点・住所補助・ピン留め）と、複数件の訪問/予定ログ（種別・単日/From-To 期間/年月/年/未定・複数行メモ）の CRUD。
3. **地図上の視覚識別＆一覧管理**: ステータス×カテゴリ別ピン表示、マップ上クイックフィルタ、絞り込み（ステータス/カテゴリ/年・期間/キーワード）・並び替え可能な地点一覧、日本百名山 100 座との連携。
4. **検索＆サジェスト（国内＋海外）**: Nominatim 全球検索＋国土地理院地名検索（日本補完）、地図タップ地点周辺の OSM 施設・ランドマーク名サジェスト。
5. **Google Drive 保存・復元**: `drive.file` 単一スコープによる `3D Visit Record/visit-records.json` への保存・復元、競合検知、履歴スナップショット退避、差分プレビュー、マージ／置き換え、1 世代 Undo。
6. **ローカル JSON バックアップ**: JSON ファイル書き出し／読み込み、および `3d_rain_viewer` お気に入り JSON の互換取り込み。
7. **プライバシー・規約・PWA**: `/privacy`・`/terms` ページ、PWA オフライン閲覧・編集、モバイル最適化。

### 4.2 初版の対象外（Out of Scope / v2 以降）
- 写真ファイルの選択・クライアント圧縮・ローカル保存・Google Drive への画像アップロード・ギャラリー表示
- バックグラウンドでの完全自動リアルタイム双方向同期（初版は明示的な保存／復元操作＋未保存通知バッジで安全性を優先）
- 複数ユーザー間の共同編集・公開マップフィード・SNS 機能
- GPX/KML トラック描画、Google マップタイムライン（Location History）インポート
- 天気・雨雲・気象予報表示（`3d_rain_viewer` の責務として分離）

### 4.3 将来の写真機能（v2）に向けた初版での先行要件
- **メタデータ枠の事前予約**: 各訪問/予定ログ（`VisitEntry`）に `photos: PhotoAttachment[]` を保持する（初版では空配列 `[]` として生成・保持し、v2 データを取り込んだ際も未実装クライアント側で破壊しない前方互換方針をとる）。
- **画像バイナリと記録 JSON の完全分離**: 将来 1 ログあたり数枚の写真を添付しても `visit-records.json` や検索・同期処理が肥大化・破綻しないよう、JSON に Base64 画像を埋め込まず、Google Drive 上は `3D Visit Record/photos/` サブフォルダ、端末内は IndexedDB の画像専用ストアへ分離できる設計を初版から確定する。

## 5. 機能要件

### 5.1 3D マップ表示・全球地形機能（F-Map）

| 要件ID | 機能名 | 要件内容 |
| :--- | :--- | :--- |
| **F-Map-01** | **WebGPU 駆動 3D 地形レンダリング（全球対応）** | JAXA AW3D30（`v3.2_global`）の Terrain-RGB タイルを WebGPU パイプラインで描画し、日本国内および海外の山岳・都市地形を立体表示する（未対応ブラウザは WebGL2 へ自動フォールバック）。背景地図および DEM タイルは OPFS キャッシュ（SWR）で高速化する。概ね緯度 `±82°` の範囲で AW3D30 標高を取得し、範囲外は平坦（標高 `null`）として安全に処理する。 |
| **F-Map-02** | **自由なカメラワーク & 標高強調** | パン・回転・チルト（ピッチ `0°〜85°`）・ズーム（`minZoom: 1.5` 〜 `maxZoom: 18`、世界全体の俯瞰から街歩きレベルまで）を操作でき、標高強調倍率（`1.0x〜3.0x`、既定 `1.5x`）を動的に変更できる。 |
| **F-Map-03** | **背景地図切替（全球＋国内注記）** | ① **OpenStreetMap（標準・全球、既定）**、② **航空写真（Esri World Imagery・全球）**、③ **国土地理院淡色地図（日本国内向け）** を設定メニューから切り替えられる。国土地理院淡色地図を選択中に海外エリアを表示した場合、タイル未存在（404 等）で描画が停止・エラー表示にならず透過フォールバックし、設定 UI 上で日本国内向けである旨を明記する。 |
| **F-Map-04** | **ステータス × カテゴリ別 3D ピン可視化** | 登録済み地点を **ステータス（訪問済み / 訪問予定）** と **4 カテゴリ（自然・観光・生活・その他）** が一目で判別できるピンマーカーで地図上に描画する。最大 1,000 地点でも 60fps を損なわない GPU レイヤー描画を行い、広域ズームではコンパクトピン（重なり軽減）、拡大ズームでは「アイコン＋地点名」ラベルへ自動切替する。ピンタップで詳細カードへ遷移し登録視点を再現する。 |
| **F-Map-05** | **マップ上クイックステータスフィルタ** | 地図画面上に常時アクセスできるフィルタピル（`すべて` / `訪問済み` / `訪問予定` ＋ 各件数）を配置し、ワンタップで地図上のピン表示を切り替えられる。 |

### 5.2 地点・訪問予定/記録管理機能（F-Spot）

| 要件ID | 機能名 | 要件内容 |
| :--- | :--- | :--- |
| **F-Spot-01** | **多様な入口からの地点登録** | 地図タップ（経緯度＋AW3D30 標高取得）、地名・施設検索結果、日本百名山プリセット、GPS 現在地のいずれからも地点を新規登録できる。登録フォーム展開時は OpenStreetMap（Overpass + Nominatim 逆ジオコーディング）から周辺施設名・山頂・駅・観光地・地名候補を取得しワンタップ入力を支援する。登録時の 3D カメラ視点（ズーム・傾き・方角）を同時保存する。 |
| **F-Spot-02** | **ステータス管理 & 予定→訪問済みワンタップ遷移** | 地点の主ステータスを **「訪問済み（`visited`）」** または **「訪問予定（`planned`）」** として管理する。「訪問予定」の地点詳細には **「訪問済みにする」** アクションを配置し、ワンタップで予定ログを実績へ確定（当日または任意日付・期間・感想メモ入力）できる。 |
| **F-Spot-03** | **日付・From-To 期間指定** | 各記録ログに日付または期間を登録できる。以下の 4 精度×単一/期間指定に対応する：<br>・**年月日（`day`）**: 単日（例 `2026-08-15`）または **From - To 日期間**（例 `2026-08-14 〜 2026-08-16`）<br>・**年月（`month`）**: 単月（例 `2025-10`）または **From - To 月期間**（例 `2025-09 〜 2025-10`）<br>・**年（`year`）**: 単年（例 `2019`）または **From - To 年期間**（例 `2018 〜 2020`）<br>・**時期未定（`none`）**: 日付なし（「いつか行きたい」予定や年代不詳の過去記録向け）<br>※開始日（From）のみ入力時は単一指定、終了日（To）入力時は開始日以降（`end >= start`）を検証し、開始と終了が同一なら単一指定として正規化する。 |
| **F-Spot-04** | **複数行メモ登録** | 各訪問/予定ログに複数行のテキストメモ（感想、アクセス手段、立ち寄り情報、予定の持ち物・調べたいこと等、1 ログあたり最大 **2,000 文字**）を登録・編集できる。 |
| **F-Spot-05** | **複数回訪問（再訪）・再訪予定ログ管理** | 1 地点に対して複数の記録ログ（過去の訪問履歴・再訪予定）を保持できる。初回登録は 1 フォームでシンプルに完結し、登録済み地点の詳細シートから「＋訪問記録を追加」「＋予定を追加」で再訪や次回の計画を追記し、個別ログの編集・削除ができる（1 地点あたり最大 **50 ログ**）。 |
| **F-Spot-06** | **編集・視点更新・ピン留め・削除・重複防止** | 地点名（最大 80 文字）、カテゴリ、主ステータス、ピン留めフラグ、3D カメラ視点（「現在の視点で更新」）を編集でき、不要な地点・ログを削除できる。登録上限は **1,000 地点** とする。近接座標（約 50m 以内）に既存地点がある場合は新規作成前に既存地点への誘導または追記を提案し、意図しない重複を防ぐ。 |
| **F-Spot-07** | **将来写真スロットの予約** | 各ログデータモデルに将来の写真添付（1 ログあたり数枚想定）用 `photos` 配列を予約し、初版データのエクスポート・クラウド保存・復元で一貫して保持する。 |

### 5.3 ナビゲーション・検索・共有機能（F-Nav）

| 要件ID | 機能名 | 要件内容 |
| :--- | :--- | :--- |
| **F-Nav-01** | **3 タブ統合ナビゲーション** | 上部ナビゲーションモーダルを **「📍 登録地点（既定）」「🔍 地名・施設検索」「🏔️ 百名山」** の 3 タブで構成する。タブ切替時のガタつき（レイアウトシフト）を抑え、一覧視認性を確保する。 |

| **F-Nav-04** | **日本百名山プリセット（全 100 座）継承** | `3d_rain_viewer` の日本百名山全 100 座（9 山域・都道府県絞り込み対応）を継承する。登録済み地点と座標照合し、百名山一覧上で **「訪問済み」「予定」バッジおよび踏破数（例: `踏破 12 / 100 座`）** を表示する。未登録の山を選択した場合はそのままワンタップで訪問済み／予定の登録へ進める。 |
| **F-Nav-05** | **GPS 現在地ジャンプ & 3D 視点共有** | 現在のズーム・傾き・方角を保ったまま GPS 現在地へ移動し地点詳細を表示する。また、現在の 3D カメラ視点・ベースマップ・標高強調（および任意で地点名）を URL クエリパラメータでワンタップ共有できる。**セキュリティ・プライバシー原則として、訪問日時・メモ・登録一覧などの個人記録は共有 URL に一切含めない。** |

### 5.4 Google Drive 保存・復元 & ローカルバックアップ機能（F-Cloud）

| 要件ID | 機能名 | 要件内容 |
| :--- | :--- | :--- |
| **F-Cloud-01** | **Google アカウント連携（非機密単一スコープ）** | Google Identity Services（GIS）を用い、`https://www.googleapis.com/auth/drive.file` 単一スコープでサインインする。連携中は接続中の Google アカウント情報（表示名・メールアドレス）を表示し、サインアウトおよびアカウント切替が可能。**Google 未連携でもローカル専用アプリとして全基本機能を利用でき、知り合いもアカウント接続前に試用できる。** |
| **F-Cloud-02** | **Google Drive への保存** | ・ユーザーのマイドライブ内に専用フォルダ `3D Visit Record/` を自動特定／作成し、`visit-records.json` へ全地点・日付・期間・メモ・カメラ視点・写真メタデータ予約枠を保存する。<br>・ローカルに変更があり未保存の場合、ヘッダーの同期ボタンに未保存インジケーター（推奨バッジ）を表示する。<br>・保存前に Drive 上のファイル更新時刻／リビジョンを照会し、**他端末での更新を検知した場合は無条件上書きをブロック**し、ユーザーに「先に Drive からマージ復元」または「ローカル内容で上書き（退避スナップショット作成付き）」を選択させる。<br>・上書き保存時には直前状態を `snapshots/` サブフォルダに自動退避（直近 5 世代保持）する。 |
| **F-Cloud-03** | **Google Drive からの復元** | ・Drive 上の `visit-records.json` を読み込み、スキーマバージョン・座標範囲・文字数・制御文字を厳格に検証する。<br>・適用前に **差分プレビュー（新規追加・更新・変更なし・削除される件数）** を提示し、**「マージ（既定・推奨：両端末の更新日時とログ単位で統合）」** と **「置き換え（Drive の内容で完全復元）」** を選択できる。<br>・復元実行直前のローカル状態を IndexedDB に 1 世代自動退避し、復元直後から **「元に戻す（Undo）」** を実行できる。 |
| **F-Cloud-04** | **ローカル JSON 入出力 & `3d_rain_viewer` 移行取込** | オフライン時や Google アカウントを使わない環境向けに、JSON ファイルの書き出し（モバイル共有シート / PC ダウンロード）および読み込みに対応する。さらに **`3d_rain_viewer` のお気に入り JSON バックアップファイル** の取り込みに対応し、一括で「訪問予定」または「訪問済み」として変換インポートできる。 |

### 5.5 規約・プライバシー・モバイル・PWA 機能（F-Legal / F-Mobile）

## 6. 非機能要件

| 分類 | 要件内容 |
| :--- | :--- |
| **グラフィックス・表示性能** | ・WebGPU 優先（未対応環境 WebGL2 自動フォールバック）で PC・スマートフォンとも 60fps の滑らかな 3D 操作を目標とする。<br>・1,000 地点登録時もマップのパン/ズームが重くならないよう GeoJSON/GPU レイヤー描画を採用し、DOM マーカーの乱立を回避する。 |
| **UI 応答性** | ・View Transitions API による軽量遷移を活用し、ユーザー操作に対する応答（INP）200ms 以内を目標とする。 |
| **データ整合性・耐障害性** | ・ローカル永続化は IndexedDB の単一レコード原子的コミット＋直列化キューでレースコンディションを防ぐ（5MB 制限のある `localStorage` に記録本体を置かない）。<br>・破損データ検知時は `storageBlocked` 状態として無言上書きを停止し、生データの救済書き出しを可能にする。<br>・`navigator.storage.persist()` によりブラウザの自動ストレージ削除を抑制する。 |
| **セキュリティ・プライバシー** | ・完全クライアントサイド処理とし、開発者のバックエンドやログへユーザーの座標・訪問履歴・メモ・OAuth アクセストークンを送信・保存しない。<br>・アクセストークンはメモリ内のみ保持し、`localStorage` / `sessionStorage` に保存しない。<br>・外部 API 由来の名称・ユーザー入力メモはすべてテキストノード描画し、XSS を構造的に防止する。<br>・`drive.file` スコープのみを使用し、アプリが作成したフォルダ・ファイル以外へ一切アクセスしない。 |
| **外部 API 利用マナー** | ・Nominatim / Overpass への照会はユーザーの明示操作（タップ・検索ボタン）時のみ実行し、連続呼び出し時のスロットリングと 30 分メモリキャッシュで負荷を最小化する。<br>・タイルデータは OPFS キャッシュで重複リクエストを抑止する。 |
| **運用コスト・インフラ** | ・Vercel Hobby プラン（静的配信のみ）＋ ユーザー自身の Google Drive 容量で稼働し、開発者側のデータベース維持費・ストレージ課金が原則発生しない構成とする。 |
| **対応ブラウザ** | 最新版の Chrome / Edge / Safari（macOS・iOS）/ Firefox。 |

## 7. 公開・展開方針（個人利用 → 知り合い紹介）

本アプリは開発者個人の実用から始め、知り合いへ URL を共有して利用してもらう前提のため、Google OAuth 運用を以下の 2 段階で進める。

| フェーズ | Google Cloud OAuth ステータス | 対象ユーザー | 主な特徴・対応 |
| :--- | :--- | :--- | :--- |
| **Phase A: 先行運用・身内テスト** | **テスト（Testing）モード** | 開発者本人 ＋ テストユーザー登録した知り合い（最大 100 名） | ・Google の公開審査待ちなしで即日 Google Drive 連携を利用可能。<br>・テストユーザー未登録の人も、Drive 連携なしのローカルモード＋JSON 保存は利用可能。 |
| **Phase B: 一般公開（URL 紹介）** | **本番（In Production）＋ ブランド確認** | 不特定の知り合い・紹介先ユーザー | ・使用スコープが非機密（Non-Sensitive）の `drive.file` のみであるため、高額な第三者セキュリティ監査（CASA）は不要。<br>・カスタムドメイン（Vercel）、`/privacy`・`/terms` ページ、同意画面ロゴ・用途説明を整えて Google の標準ブランド確認（Brand Verification）を通過させる。 |

## 8. 初版（v1）受け入れ基準（完了条件）

1. 地図タップ・検索（国内および海外都市/ランドマーク）・百名山・現在地の各経路から、地点の **「訪問済み」「訪問予定」** を日付（単日 / From-To 期間 / 年月 / 年 / 未定）および複数行メモ付きで登録・再読み込み後も復元保持できる。
2. 登録した地点に対して **再訪ログの追記**、**「訪問予定 → 訪問済み」への遷移**、**登録時 3D カメラ視点の再現**、および地図上のステータスフィルタ・一覧絞り込み（年/期間オーバーラップ含む）が正常動作する。
3. Google サインイン後に **Google Drive（`3D Visit Record/visit-records.json`）へ保存**でき、別ブラウザまたはローカル初期化状態から **差分プレビュー確認のうえマージ復元／置き換え復元** が成功し、直前状態への **元に戻す（Undo）** も動作する。
4. 他端末で Drive データが更新されている状態で保存を試みた場合、**競合検知により無言上書きが防止**され、マージまたは退避付き上書きを選択できる。
5. Google Drive 未連携でもローカル利用および JSON ファイルでの保存・復元（`3d_rain_viewer` お気に入り JSON 取込含む）が完結し、`/privacy`・`/terms` ページが閲覧できる。
